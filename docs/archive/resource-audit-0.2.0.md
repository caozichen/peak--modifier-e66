# PEAK Workshop 0.2.0 安全与资源释放检查

检查日期：2026-10-29，Asia/Shanghai。对象为独立桌面端、游戏插件、部署/升级脚本及交付文件。

## 结论与边界

源码复查、Release 构建和离线测试已通过，未观察到生产管道测试的资源数随请求次数持续增长。不能据此承诺绝对安全或不存在内存泄漏：尚未启动 PEAK，没有真实 Unity/Mono 长时间资源采样，也未实际安装和撤销游戏内补丁。

源码没有 HTTP/TCP/UDP 上传、账户采集、自启动或服务安装逻辑；Win32 调用仅核验本机命名管道对端身份。游戏接入使用 BepInEx/UnityDoorstop。第三方包核对上游发布 SHA256，但第三方组件未接受完整源码/二进制安全审计。

## 本轮修复

| 问题 | 处理 |
|---|---|
| 实际状态枚举嵌套在 CharacterAfflictions 中，按顶层类型查询会使角色初始化失败 | 改为 GetNestedType，并用真实程序集反射和生产 IL 检查验证 |
| 新增 Harmony 转译签名依赖游戏 Mono 的 mscorlib，旧 netstandard 引用无法编译 | 生产项目使用游戏 Mono 引用；新 Patch 六参数重载；最终 0 警告/0 错误 |
| 延迟跳跃不在 RPC 立即施力，临时改字段会错过施力点 | 在真实延迟协程读取原冲量的位置调整，保留原字段 |
| 无限使用只拦截删除入口会留下 consuming=true 或各客户端不同步 | 在本地发起端处理次数/消耗协程，保留回调，跳过消耗广播；不拦接收 RPC |
| 失去房主权限后旧设置可能在再次成为房主时自动恢复 | 关闭不可用功能、更新状态修订号并拒绝旧指令；重新获得权限需手动开启 |
| 一项恢复抛错可能跳过余下清理 | 重置/释放/自身补丁撤销分别执行；Dispose 的 finally 始终清空角色和静态适配器引用 |
| 逐帧数值覆盖可能累乘或留下历史场景引用 | 只改变当前计算结果/参数；标记最多 64 个弱引用，迷雾显示最多 16 个弱引用，清理时恢复并移除 |

沿用 0.1.1 的可取消异步管道、最多 8 个主线程待处理请求、64 KiB 帧上限、当前 Windows 用户和本机 PID 校验。修改需要当前会话与状态修订号，旧连接排队的操作不会自动重连执行。全部功能默认关闭；角色/场景变化、死亡/昏迷、断线和主线程恢复后的 3 秒失联会关闭功能。

管道压力测试预热后请求阶段句柄数为 274，采样线程数为 17。100 次重连并停止后为 274 个句柄、17 个线程、GC 堆 624,072 字节。最终采样相对重连前句柄差 +2、堆差 -3,051,160 字节。GC 堆在请求过程中波动，进程级数据受 JIT/线程池/日志影响；这只是独立 .NET 测试进程的短时证据，不能代替游戏内内存检查。原始样本在 `验证结果/自动化测试.json`。

离线实际 IL 检查使用 .NET Framework，并以元数据方式检查该宿主不支持的游戏默认接口方法；替身分支测试运行在 .NET 10。它们均不能确认 Unity Mono detour/原生调用兼容性。试过的 .NET 10 直接加载旧 Harmony IL 读取器不兼容，因此未把那种宿主视为游戏运行验证。

## 关闭、停用和卸载

| 操作 | 功能 | 补丁与通信 | DLL/加载器 |
|---|---|---|---|
| 恢复全部 | 关闭全部，恢复可恢复的视觉/派生参数 | 自身补丁和通信保留 | 保留在进程中 |
| 关闭窗口/失联 | 尝试关闭，失联由继续执行的游戏主线程兜底 | 游戏插件仍可等待连接 | 保留在进程中 |
| 停用插件 | 关闭、恢复并释放引用 | 仅撤销自己的 Harmony ID；最后回执后停通信，组件随后停止 Update | 随游戏退出释放 |
| 退出游戏 | 进程结束 | 由进程退出回收 | OS 回收进程内存和句柄 |
| 游戏关闭后卸载 | 下次不再加载 | 按自有文件哈希移除，共享加载器保留 | 移除自有磁盘文件 |

Mono 默认域不支持单独卸载某个已加载程序集。本程序不承诺热卸载 DLL。界面会保留“已停用”，同一游戏 PID 不再重连；重启游戏后可重新连接。无法确认恢复或补丁撤销时会提示重启，不把未收到回执当成成功。

发生过的玩法变化不恢复为旧快照。游戏暂停/主线程卡住时不能保证立即执行恢复。负重与视觉恢复是尽力执行；销毁对象和其他 Mod 后来的修改不会被强行覆盖。卸载前必须退出游戏。
